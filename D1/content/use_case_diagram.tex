\section{Use Case Diagram}

Questa sezione descrive i principali casi d’uso del sistema \textbf{Rinova}, suddivisi per categoria di attore. 
Per ogni gruppo funzionale viene riportato il relativo \textit{Use Case Diagram (UCD)} e la descrizione testuale 
dei singoli requisiti funzionali (\textit{RF}) con riassunto, flusso principale ed eventuali eccezioni.

\paragraph*{Use Case RF-01: Registrazione utente}
\subparagraph*{Riassunto:}
Questo use case descrive come l'utente anonimo effettua la prima registrazione alla webapp.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente anonimo visualizza la schermata di registrazione con il form contenente i campi obbligatori: Nome, Cognome, Email, Codice fiscale, Numero di telefono, Indirizzo di residenza e Password.
    \item L’utente compila i campi obbligatori; quindi preme il pulsante ``Registrati''.
    \item L'utente accetta i termini e condizioni per la privacy.
    \item Il sistema valida i dati inseriti (campi obbligatori, formato di nome/cognome, formato email, unicità email e codice fiscale, formato numero di telefono, criteri password).
    \item Se la validazione ha esito positivo, il sistema crea il profilo utente e invia una email di conferma contenente un link di verifica.
    \item L’utente clicca il link nella email per confermare l’indirizzo; il sistema finalizza la registrazione e imposta lo stato account a ``attivo''.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se mancano campi obbligatori, il sistema segnala gli errori e impedisce la registrazione.
    \item Se email o codice fiscale sono già registrati, il sistema notifica la collisione e richiede correzione.
    \item Se il formato della password non soddisfa i criteri, il sistema richiede una password conforme.
\end{itemize}

% ------------------------
\paragraph*{Use Case RF-02: Login utente}
\subparagraph*{Riassunto:}
Questo use case descrive come l'utente autenticato effettua il login nella webapp.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente visualizza la schermata di login con campi Email/Username e Password e opzioni di autenticazione esterna (Google, Microsoft).
    \item L’utente inserisce Email e Password e preme ``Accedi''.
    \item Il sistema verifica le credenziali: se corrette reindirizza l’utente alla homepage personalizzata; in caso contrario mostra errore.
    \item Se l’utente seleziona un provider OAuth2 (es. Google), viene reindirizzato alle schermate del provider; dopo autenticazione corretta il sistema accetta il token e apre la homepage.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se email/password non corrispondono, il sistema mostra un messaggio di errore e offre il recupero password.
    \item Se l’autenticazione tramite provider esterno fallisce o è annullata, il sistema ritorna alla schermata di login e notifica l’errore.
\end{itemize}

% ------------------------
\paragraph*{Use Case RF-02.1: Recupero password}
\subparagraph*{Riassunto:}
Questo use case descrive come un utente che ha dimenticato la password richiede e completa il reset della password.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente seleziona ``Recupera password'' dalla schermata di login e inserisce il proprio indirizzo email.
    \item Il sistema verifica che l’email sia registrata e invia un’email contenente un link sicuro per il reset (con token a scadenza).
    \item L’utente clicca il link e viene reindirizzato a una pagina per inserire la nuova password.
    \item L’utente inserisce la nuova password che deve rispettare i criteri di sicurezza; il sistema aggiorna la password e conferma l’avvenuto reset.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se il token è scaduto o invalido, il sistema richiede una nuova richiesta di recupero.
\end{itemize}

\paragraph*{Use Case RF-03: Accesso all'area personale}
\subparagraph*{Riassunto:}
Questo use case descrive come un utente autenticato accede alla propria area personale per visualizzare il profilo e le impostazioni.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente effettua il login con successo.
    \item Dalla navbar selezionando il proprio profilo può accedere all'area personale.
    \item Il sistema autentica la sessione e mostra la pagina con i dati del profilo, impostazioni dell’account e le funzionalità disponibili (modifica dati, notifiche, gestione privacy).
    \item L’utente può navigare le sotto-sezioni per modificare informazioni o avviare operazioni (es. cancellazione account).
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se la sessione è scaduta o non autenticata, il sistema reindirizza alla pagina di login.
    \item Se l’utente non ha i permessi necessari per una funzionalità, il sistema mostra un messaggio di accesso negato.
\end{itemize}

% ------------------------
\paragraph*{Use Case RF-03.1: Modifica dati personali}
\subparagraph*{Riassunto:}
Questo use case descrive come un utente modifica o elimina (se permesso) i propri dati personali dall’area personale.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente autenticato entra nell’area personale.
    \item Il sistema presenta il form con i dati correnti; l’utente modifica i campi desiderati.
    \item L’utente salva le modifiche; il sistema valida i nuovi dati e, se validi, li salva aggiornando il profilo.
    \item Il sistema registra l’operazione nel registro attività e notifica l’utente dell’avvenuta modifica.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se i dati inseriti non superano la validazione (formati errati, duplicati), il sistema mostra errori e non salva.
    \item Alcuni campi obbligatori non possono essere eliminati: il sistema impedisce la rimozione e informa l’utente.
\end{itemize}

% =========================================================
\paragraph*{Use Case RF-03.2: Cancellazione dell'account}
\subparagraph*{Riassunto:}
Questo use case descrive come l'utente può richiedere la cancellazione permanente del proprio account.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente autenticato apre l’area personale e seleziona ``Elimina definitivamente''.
    \item Il sistema mostra un avviso con informazioni sulle conseguenze e chiede conferma esplicita.
    \item Dopo la conferma, il sistema avvia il processo di cancellazione: rimuove i dati personali in conformità con le normative.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se l’utente non fornisce conferma esplicita, la cancellazione non procede.
    \item Se esistono vincoli legali o dati che devono essere conservati (es. obblighi normativi), il sistema informa l’utente e non cancella tali dati; esegue invece l’anonimizzazione.
\end{itemize}

% =========================================================
\paragraph*{Use Case RF-04: Logout utente}
\subparagraph*{Riassunto:}
Questo use case descrive come un utente autenticato esegue il logout dalla webapp per terminare la propria sessione e garantire la sicurezza del proprio account.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente autenticato, dal menù dell’area personale, seleziona l’opzione ``Logout''.
    \item Il sistema invalida la sessione corrente, eliminando i token di autenticazione locali e di sessione.
    \item Il sistema reindirizza l’utente alla homepage pubblica o alla schermata di login.
    \item L’utente non ha più accesso alle funzionalità riservate fino a un nuovo login.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se la sessione è già scaduta, il sistema mostra un messaggio informativo e reindirizza comunque alla homepage pubblica.
    \item Se si verifica un errore nella disconnessione (es. token non trovato o già invalido), il sistema elimina comunque i dati locali e forza il logout.
\end{itemize}

\paragraph*{Use Case RF-05: Visualizzazione dati energetici personali}
\subparagraph*{Riassunto:}
Questo use case descrive come l'utente visualizza i propri dati energetici (consumi, produzione, stato batteria, risparmio CO$_2$) tramite le dashboard dell'applicazione.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente autenticato accede alla sezione Dashboard, Produzione Live o Storico Produzione.
    \item Il sistema interroga il database e i servizi di monitoraggio per recuperare i dati relativi a consumi, produzione, livello della batteria (se presente) e risparmio di CO$_2$ calcolato.

    \item L'utente può filtrare la visualizzazione per intervallo temporale (es. giorno, settimana, mese) o visualizzare i dati in tempo reale.
\end{enumerate}

\subparagraph*{Eccezioni:}

\paragraph*{Use Case RF-07: Gestione impianti energetici}
\subparagraph*{Riassunto:}
Questo use case descrive le operazioni di registrazione, visualizzazione dettagli e segnalazione malfunzionamenti degli impianti di produzione energetica associati dell'utente.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente accede alla sezione "Impianti".
    \item \textbf{Registrazione:} L'utente seleziona "Aggiungi impianto" e compila il form con i dati obbligatori: codice identificativo, potenza nominale, posizione geografica, tipo di impianto, data di installazione. Il sistema valida i dati e registra il nuovo impianto, ponendo il suo stato in "Attesa".
    \item \textbf{Visualizzazione:} L'utente può visualizzare i dettagli del proprio impianto cliccando l'apposito pulsante "Visualizza dettagli".
    \item \textbf{Segnalazione:} L'utente seleziona un impianto esistente e ne segnala un guasto attraverso l'apposito pulsante.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se in fase di registrazione mancano dati obbligatori o il codice identificativo è già presente nel sistema, l'operazione viene annullata con un messaggio di errore.
\end{itemize}

\paragraph*{Use Case RF-08: Ricerca CER}
\subparagraph*{Riassunto:}
Questo use case descrive come l'utente cerca una Comunità Energetica a cui inoltrare una richiesta di adesione.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente accede alla sezione "Gestione CER".
    \item Se l'utente non fa parte di alcuna CER vedrà il pulsante "Trova CER" lo preme ed inserisce una parola chiave nella barra di ricerca (Nome della CER o Codice Identificativo).
    \item Il sistema interroga il database delle CER attive e restituisce una lista di risultati pertinenti.
    \item Per ogni risultato, il sistema mostra un'anteprima contenente: Nome CER, numero di membri attuali e descrizione.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se la ricerca non produce risultati, il sistema mostra il messaggio "Nessuna CER trovata".
\end{itemize}

% ------------------------

\paragraph*{Use Case RF-09: Richiesta adesione CER}
\subparagraph*{Riassunto:}
Questo use case descrive il processo con cui un utente invia una richiesta formale per entrare a far parte di una CER.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item Dalla lista dei risultati di ricerca (RF-08), l'utente preme il pulsante "Richiedi adesione".
    \item Il sistema verifica che l'utente non sia già membro o non abbia già una richiesta pendente per quella comunità.
    \item Il sistema crea una nuova richiesta di adesione con stato "In attesa" e la inserisce nella lista delle richieste visibili all'amministratore della CER.
    \item Il sistema conferma all'utente l'avvenuto invio della richiesta.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se l'utente è già membro della CER selezionata, il sistema mostra un avviso e impedisce una nuova richiesta.
    \item Se esiste già una richiesta in stato "In attesa" per la stessa CER, il sistema notifica l'utente che la richiesta è già in fase di valutazione.
\end{itemize}

\paragraph*{Use Case RF-10: Gestione membri della CER (Admin)}
\subparagraph*{Riassunto:}
Questo use case descrive come l’amministratore della CER gestisce l’elenco dei membri (visualizza, modifica).

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’amministratore effettua login con privilegi admin e accede alla pagina della CER, visualizzando la tabella di gestione membri.
    \item Il sistema mostra la lista dei membri con dati identificativi e stato di partecipazione.
    \item L’amministratore può selezionare un membro per modificarne lo stato o visualizzarne i dettagli.
\end{enumerate}

% ------------------------
\paragraph*{Use Case RF-11: Approvazione richieste di adesione (Admin)}
\subparagraph*{Riassunto:}
Questo use case descrive come l’amministratore approva o rifiuta le richieste di adesione alla CER.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’amministratore accede all’elenco delle richieste di adesione pendenti attraverso l'apposito pulsante ``richieste in attesa'' nel pannello di gestione membri.
    \item Seleziona una richiesta per visualizzare i dettagli (dati utente, indirizzo, disponibilità impianto, codice POD).
    \item L’amministratore può ora decidere se approvare o rifiutare la richiesta premendo gli appositi pulsanti: se approva, il sistema invia una notifica email e imposta lo stato a ``membro attivo''; se rifiuta, invia notifica con motivazione.
    \item Tutte le decisioni vengono registrate nel registro attività.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se mancano informazioni necessarie per la valutazione, il sistema richiede integrazione dati.
    \item In caso di conflitti (es. POD già associato), il sistema segnala la problematica e blocca l’approvazione.
\end{itemize}

\paragraph*{Use Case RF-13: Visualizzazione dati energetici e reportistica}

\subparagraph*{Descrizione:}

\paragraph*{Use Case RF-14: Gestione bacheca avvisi}
\subparagraph*{Riassunto:}
Questo use case descrive le operazioni di creazione, modifica e cancellazione delle comunicazioni ufficiali da parte dell'amministratore della CER, destinate a essere visualizzate da tutti i membri della comunità.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item \textbf{Pubblicazione:} L'amministratore seleziona il pulsante "+" e compila i campi obbligatori: Titolo, Testo del messaggio e Tipo (es. Info, Avviso, Manutenzione, Evento). Alla conferma, il sistema pubblica il messaggio rendendolo visibile a tutti i membri e invia una notifica (cfr. RF-16).
    \item \textbf{Rimozione:} L'amministratore elimina un avviso selezionandolo e premendo l'icona del cestino. Il sistema lo rimuove permanentemente dalla bacheca dei membri.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se l'amministratore tenta di pubblicare un avviso con titolo o corpo del messaggio vuoti, il sistema impedisce l'operazione segnalando l'errore.
    \item Se il sistema di notifica fallisce l'invio ai membri, l'avviso viene comunque pubblicato in bacheca.
\end{itemize}

\paragraph*{Use Case RF-15: Visualizzazione notifiche}
\subparagraph*{Riassunto:}
Questo use case descrive come l'amministratore consulta la sezione dedicata ai messaggi ricevuti dai membri della sua CER.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’amministratore di clicca sull'icona delle notifiche presente nella pagina della CER (generalmente accompagnata da un contatore di elementi non letti).
    \item Il sistema mostra l'elenco cronologico delle notifiche ricevute, distinguendo visivamente quelle "Non lette" da quelle già consultate.
    \item L'amministratore clicca su una specifica notifica.
    \item Il sistema marca la notifica come "Letta", decrementa il contatore delle notifiche pendenti.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se non sono presenti notifiche, il sistema mostra un messaggio informativo ("Nessuna notifica presente").
\end{itemize}

\paragraph*{Use Case RF-18: Abbandono CER}
\subparagraph*{Riassunto:}
Questo use case descrive la procedura formale con cui un membro della Comunità Energetica decide volontariamente di recedere dal contratto di partecipazione, interrompendo la condivisione dell'energia e la maturazione degli incentivi.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente accede all'area della propria CER.
    \item L'utente apre il menù di gestione iscrizione
    \item L'utente seleziona la funzione "Abbandona CER".
    \item Il sistema visualizza un messaggio di allerta (warning) che riepiloga le conseguenze dell'azione:
    \begin{itemize}
        \item Perdita immediata del diritto agli incentivi futuri.
        \item Disattivazione del monitoraggio ai fini della condivisione energetica.
        \item Impossibilità di annullare l'operazione una volta confermata.
    \end{itemize}
    \item L'utente conferma la volontà di procedere.
    \item Il sistema registra la modifica.
\end{enumerate}

\paragraph*{Use Case RF-AS-01/02/03: Gestione ciclo di vita CER}
\subparagraph*{Riassunto:}
Questo use case descrive le operazioni di amministrazione (creazione, modifica ed eliminazione) delle Comunità Energetiche sulla piattaforma da parte dello staff Rinova.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item Viene stipulato un contratto fra Rinova e la CER desiderosa di collaborare
    \item \textbf{Registrazione (RF-AS-01):} L'amministratore di sistema opera sul database e inserisce i dati anagrafici (Denominazione, P.IVA, Indirizzo). Il sistema richiede di associare un indirizzo email per il primo amministratore locale. La CER viene creata.
    \item \textbf{Modifica (RF-AS-02):} L'amministratore di sistema opera sul database al fine di modificare una CER esistente nella lista. Può aggiornare i dati anagrafici o riassegnare il ruolo di admin locale a un altro utente.
    \item \textbf{Eliminazione (RF-AS-03):} L'amministratore elimina una CER dal database del sistema. La CER e i dati associati vengono rimossi o anonimizzati.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se si tenta di registrare una CER con una P.IVA già presente, il sistema blocca l'operazione.
\end{itemize}

\paragraph*{Use Case RF-AS-04: Validazione impianto}
\subparagraph*{Riassunto:}
Questo use case descrive il processo di approvazione tecnica di un nuovo impianto registrato dagli utenti, necessario per renderlo operativo nel sistema di calcolo.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’amministratore di sistema compie una verifica d'esistenza e correttezza dei dati dell'impianto da verificare.
    \item Se i dati sono conformi, l'amministratore lo valida.
    \item Il sistema aggiorna lo stato dell'impianto in "Attivo", abilita l'ingestione dei dati nel sistema e invia una notifica di conferma all'utente proprietario.
\end{enumerate}

\subparagraph*{Eccezioni:}
\begin{itemize}
    \item Se i dati non sono conformi (es. POD inesistente o potenza errata), l'amministratore rifiuta la validazione inserendo una motivazione.
\end{itemize}

\paragraph*{Use Case RF-10: Apertura Ticket Segnalazioni}
\subparagraph*{Riassunto:}
Questo use case descrive la procedura con cui un utente (Membro o Utente semplice) apre una segnalazione per richiedere assistenza tecnica o amministrativa allo staff di Rinova.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item L’utente accede alla sezione "Supporto".
    \item I'utente compila il modulo con:
    \begin{itemize}
        \item Categoria (es. Problema Tecnico, Fatturazione e Contratti, Feedback, Gestione Account).
        \item Oggetto della richiesta.
        \item Descrizione dettagliata del problema.
        \item Eventuali allegati (screenshot o documenti).
    \end{itemize}
    \item L'utente conferma l'invio.
    \item Il sistema registra il ticket nel database assegnandogli un ID univoco, imposta lo stato su "Aperto" e mostra una conferma a video.
    \item Il ticket diventa visibile nella lista "I miei Ticket" dell'utente per monitorarne l'evoluzione.
\end{enumerate}

\paragraph*{Use Case RF-AS-05: Gestione Ticket di Supporto}
\subparagraph*{Riassunto:}
Questo use case descrive le attività del Super Admin (Staff Rinova) volte alla risoluzione delle problematiche segnalate dagli utenti.

\subparagraph*{Descrizione:}
\begin{enumerate}
    \item Il Super Admin accede alla lista dei ticket.
    \item L'Admin seleziona un ticket per visualizzarne i dettagli e lo storico messaggi.
    \item L'Admin può eseguire diverse azioni:
    \begin{itemize}
        \item \textbf{Rispondere:} Inserisce un messaggio di risposta che verrà notificato all'utente.
        \item \textbf{Cambiare Stato:} Aggiorna lo stato del ticket (es. da "Aperto" a "In Lavorazione" o "Risolto").
    \end{itemize}
    \item Il sistema salva le modifiche e aggiorna la vista lato utente.
\end{enumerate}
